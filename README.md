# Human Loop

人と話す前の準備を、短くわかりやすくまとめるWebアプリです。自分と相手のInstagramの公開情報を別々に確認し、相手の関心、共通点、話しかける言葉、紹介する商品の候補などを整理します。AIは初期設定でローカルのOllamaを使います。

## この公開リポジトリについて

ここで公開しているのはアプリのコードです。GitHubのページを開くだけではアプリは動きません。今の構成は、Mac上のNode.jsサーバー・Ollama・Opera Neonを使います。Vercelにコードを置くだけでも、これらのローカル機能は移行されません。

APIキーや個人用の設定は `.env.local` に保存し、公開しないでください。テスト中の写真・調査メモを置く `artifacts/` と、携帯用の接続情報 `.mobile/` もGitの対象外です。Instagramの読み取りは公開情報だけを対象とし、取得できなかった情報を確認済みとは扱いません。

## 起動

```bash
npm install
npm run dev
```

ブラウザで `http://localhost:3000` を開きます。

## 携帯用リンク（パスワードなし）

Macでサイトを起動したまま、別のターミナルで次を実行します。

```bash
brew install cloudflared
npm run mobile
```

表示された `https://...trycloudflare.com` が携帯用のリンクです。パスワード入力はありません。
リンクの状態は `.mobile/access.json` に保存されます。このファイルは公開フォルダ外にあり、Gitにも含めません。

- リンクを知っている人は、画面・API・Instagram確認を使えます。リンクを不用意に共有しないでください。
- Macが起動し、サイトと `npm run mobile` が動いている間だけ利用できます。Macをスリープさせるとつながりません。
- 携帯用コマンドを `Ctrl+C` で止めると接続を停止します。再起動するとURLが変わります。
- 外部接続はCloudflare経由です。Cloudflare Quick Tunnelは一時的なテスト用で、常設公開には向きません。
- Macの3000番を直接公開せず、127.0.0.1:3001の限定ゲートだけを接続します。接続先パスは必要な画面・APIに限定しています。

認証・経路制限などのテスト: `npm run test:mobile`

## AI設定

初期設定は、APIキー不要のローカルOllamaです。Ollamaを起動し、モデルを一度だけ取得してください。

```bash
ollama serve
ollama pull qwen3:4b-instruct
```

`.env.local` では次の設定を使います。

```env
AI_PROVIDER=ollama
OLLAMA_MODEL=qwen3:4b-instruct
OLLAMA_BASE_URL=http://127.0.0.1:11434
```

OpenAIに戻す場合だけ、`AI_PROVIDER=openai` と `OPENAI_API_KEY` を設定します。キーはチャットやGitに貼らないでください。

## Opera Neon

Opera Neonを使ったInstagram公開情報の確認は、ローカルのBrowser CLIを使う想定です。Opera Neonをインストール・ログインした上で、次を一度だけ実行します。

```bash
npm install -g opera-browser-cli
opera-browser-cli setup
```

アプリの「確認して準備ノートをつくる」は、あなたと話す相手の公開プロフィールを開き、公開されている投稿とストーリーズも確認して、共通点のヒントを準備メモへ入れます。ログインが必要な情報や非公開情報は対象にしません。

お話しする時間（5分・30分・1時間・2時間）に合わせて、会話の時間帯ごとの優先度も準備ノートに表示します。

## 自動おすすめ

相手の公開情報だけから、活動・目的と商品の使い道をつなげます。例：ボクシング→身体づくり→ピラティス、登山→持久力→ランニング、教材や文章の準備→AI。商品名が投稿に書かれていなくても候補を出し、短い理由を表示します。

間接的な候補はローカルOllamaにも相談します。実際の本文にある引用と商品の用途を確かめ、推測は「候補」として扱います。Ollamaが遅い・停止中の場合も、根拠がある活動と用途のつながりで候補を返します。職業名や「健康」だけで商品を決めつけたり、あなたの情報を相手の情報に混ぜたりしません。手動の選択も引き続き使えます。

おすすめのテスト：`node --test test/offer-*.test.mjs`

## 相手の興味と商品の候補は別に扱います

興味の一覧は、本人のプロフィールの肩書き・主な活動を優先し、本人の複数の投稿で繰り返すテーマを確かめて最大3つにまとめます。確認できた関心が少ないときは、無理に3つにしません。ボクサーの中心テーマは「ボクシング」であり、紹介する候補の「ピラティス」に置き換えません。

画像の自動説明、別の人のコメント、画面の案内、ログインできず読めなかったストーリーズ、操作者の情報は根拠にしません。Ollamaが追加するテーマも、相手の実際の本文に引用がある場合だけ採用します。興味・会話の入口・話しかける言葉・準備動画は、この同じ確認結果から作ります。Ollamaが使えないときも、プロフィールや本人の投稿で確認できた中心テーマを保ちます。

全テスト：`npm test`
